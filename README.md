**Job Scout** is a privacy-first Retrieval-Augmented Generation (RAG) platform that bridges the semantic gap between applicants and Applicant Tracking Systems (ATS). By utilizing local AI models and vector similarity search, it matches candidates to ideal roles. It generates highly tailored application materials—all without transmitting sensitive personal data to external cloud APIs.

## ✨ Key Features

- **Semantic Vector Matching:** Uses `all-MiniLM-L6-v2` and PostgreSQL (`pgvector`) with an HNSW index to match resumes to job descriptions based on contextual meaning, not just exact keywords.
- **100% Offline AI Generation:** Integrates `Llama-3.2-3B-Instruct` locally via PyTorch to generate ATS-optimized cover letters and resume bullets, guaranteeing zero data leakage.
- **Automated Job Scraping:** Asynchronous Celery workers periodically extract and index job listings from target career portals.
- **Microservices Architecture:** Fully containerized environment comprising FastAPI, Next.js, Redis, and PostgreSQL.
- **Sub-10ms Query Latency:** Optimized vector indexing guarantees rapid candidate-to-job matching, verified by included benchmarking scripts.

---

## 🏗️ Architecture

Job Scout is built on a containerized microservices architecture:

1. **Frontend (Next.js):** React 19 UI consuming chunked plain-text HTTP streams for real-time token rendering.
2. **Backend API (FastAPI):** Python REST API handling orchestration, RAG logic, and model inference.
3. **Database (PostgreSQL + pgvector):** Relational and vector storage for resumes and job embeddings (384-dimensional).
4. **Message Broker (Redis):** Task queuing for background jobs.
5. **Worker (Celery):** Handles asynchronous web scraping and bulk embedding tasks.
6. **Scheduler (Celery-Beat):** Triggers periodic pipeline updates.

## 🚀 Quick Start

**1. Clone the repository**
```bash
git clone https://github.com/ShrishPC/Job-Scout.git
cd job-scout
```

**2. Start the Docker containers**
```bash
docker compose up --build -d
```
*Note: On the first boot, the backend will download the `all-MiniLM-L6-v2` and `Llama-3.2` models. This may take a few minutes depending on your internet connection.*

**3. Access the Application**
- **Frontend UI:** [http://localhost:3000](http://localhost:3000)
- **Backend API Docs (Swagger):** [http://localhost:8001/docs](http://localhost:8001/docs)

## 📊 Performance Benchmarking

Job Scout includes comprehensive empirical benchmarking suites testing real API endpoints and vector index scaling:

- **Real Production API Benchmark (`POST /jobs/matches`):**
  Evaluates end-to-end HTTP matching with `SET LOCAL hnsw.ef_search = 400` across 10,000 and 100,000 job rows:
  - **10k Rows:** Two-Stage CTE **8.43 ms** (Recall@10: 0.731) vs Legacy **90.01 ms** (10.7x speedup).
  - **100k Rows:** Two-Stage CTE **9.08 ms** (Recall@10: 0.750) vs Legacy **890.88 ms** (98.1x speedup).
  - **Sequential Baseline (Triplicate):** Run 1: 29.31 ms, Run 2: 29.79 ms, Run 3: 28.68 ms.
  ```bash
  docker compose exec backend python scripts/benchmarks/benchmark_api_matches.py
  ```

- **Retrieval Quality Suite (28 Resumes x 560 Jobs = 15,680 Labels):**
  Evaluates in-Python vs production SQL retrieval ranking:
  - **Two-Stage SQL (k=100):** NDCG@10 = 0.985, P@5 = 0.986, P@10 = 0.989, MRR = 1.000 (100% top-10 overlap, Kendall $\tau = 1.000$ vs Legacy).
  ```bash
  docker compose exec backend python evaluation/evaluate_retrieval.py
  ```

## 🛡️ Scraping and Responsible Use

Job Scout includes multi-portal job harvesting capabilities designed for personal search and research workflows:
- **Personal, Low-Volume Use**: Scraping tasks are scheduled at conservative intervals (Celery-Beat default every 10 minutes) and intended exclusively for individual job search optimization.
- **Terms of Service & Robots Policy**: Users are responsible for adhering to the robots exclusion standard (`robots.txt`) and specific Terms of Service of each source portal (LinkedIn, Indeed, Naukri, RemoteOK, We Work Remotely).
- **Human-in-the-Loop Philosophy**: Job Scout does **not** automate application submissions. All candidate materials generated by the system are designed for human review, refinement, and manual submission by the applicant.

---

## 🔒 Security & Privacy

- **Offline Inference:** All AI/ML processing occurs on the host CPU/GPU. No resume data is sent to OpenAI, Anthropic, or any external vendor.
- **Vulnerability Mitigation:** Employs parameterized SQL queries to prevent injection attacks and UUID-based file handling to block Path Traversal.
